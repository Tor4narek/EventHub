# EventHub

EventHub помогает пользователю MAX находить мероприятия по интересам. Бот
проводит онбординг через выбор тегов, предлагает подборку и управляет
напоминаниями. MAX WebApp показывает каталог с поиском и фильтрами. Отдельная
админка позволяет работать с мероприятиями и тегами.

## Состав проекта

| Папка | Назначение |
| --- | --- |
| `EventHubAPI` | .NET 10 API, MAX-бот, планировщик, EF Core, MinIO-клиент |
| `EventHubAdmin` | React-админка |
| `EventHubFrontend` | React MAX WebApp |
| `deploy` | Caddy и инструкция развёртывания |

PostgreSQL хранит пользователей, теги и мероприятия. MinIO хранит изображения.
Бот, обработка его входящих событий и планировщик работают в одном экземпляре
API. Оба фронтенда отправляют `/api/*` через собственный Nginx в контейнер API.

## Запуск локально

1. Скопируйте корневой `.env.example` в `.env` и заполните пустые значения.
   `Minio__AccessKey` должен совпадать с `MINIO_ROOT_USER`, а
   `Minio__SecretKey` — с `MINIO_ROOT_PASSWORD`. JWT-ключ должен содержать не
   менее 32 байт. Для пароля администратора нужен хеш в формате, который
   выдаёт `dotnet run --project EventHubAPI/EventHubAPI -- --hash-admin-password`.
2. Из корня репозитория выполните одну команду:

   ```bash
   docker compose up --build -d
   ```

Порты по умолчанию: API — `http://localhost:8456`, админка —
`http://localhost:8457`, WebApp — `http://localhost:5174`, PostgreSQL — `5432`,
MinIO API — `9500`, MinIO Console — `9501`. Все они привязаны к localhost.
Порты задаются переменными в корневом `.env`. API применяет существующие
миграции EF Core при старте.

Остановить контейнеры: `docker compose down`. Повторно запустить:
`docker compose up -d`. Именованные тома с БД и изображениями сохраняются при
`down`; команда `down -v` их удаляет.

## Проверка сценария

1. В админке войдите под учётными данными из `.env`, создайте теги и
   опубликованное мероприятие с актуальной датой.
2. Откройте бота в MAX, выберите интересы и запросите подборку.
3. Откройте WebApp из меню бота, проверьте каталог и фильтры.
4. Проверьте сохранение мероприятия и напоминание.

В чистой БД демонстрационных мероприятий нет; их нужно создать через админку.
Для проверки через MAX требуется настроить токен и публичный HTTPS webhook.
Импорт из внешних источников пока не реализован: административный метод
возвращает 501. Для публичной технической проверки потребуется обновить
`DATA-API.yaml` реальным адресом API и приложить экспорт OpenAPI.

## Развёртывание

Инструкция по Ubuntu, GitHub Actions, DNS, сертификатам и настройке MAX — в
`deploy/README.md`. Production-профиль запускает Caddy, который выдаёт HTTPS
для трёх доменов. При автодеплое `.env` собирается из `.env.example` и
отдельных GitHub Secrets; локальный `.env` не загружается. После подключения
мини-приложения к боту установите переменную GitHub `MAX_WEBAPP_NAME`.

Тесты API: `dotnet test EventHubAPI/EventHubAPI.sln`. Локальные сборки фронтов:
`npm ci && npm run build` в каждой из двух фронтовых папок.
