# Импорт мероприятий ITMO Events

Импорт работает без модели. В админке откройте «Импорт», вставьте до 50 прямых ссылок (по одной на строку), затем проверьте каждый результат. «Сохранить проверку» сохраняет неполные данные в очереди. «Создать черновик» требует название, описание, место, будущую дату и хотя бы один тег. Публикация выполняется отдельно в разделе «Мероприятия».

## API

Все методы требуют JWT с ролью Admin.

- `POST /api/admin/imports`, тело `{ "urls": ["https://itmo.events/events/122043"] }` — возвращает `202` и `importId`.
- `GET /api/admin/imports` — последние 20 запусков с результатами.
- `GET /api/admin/imports/{importId}` — состояние запуска.
- `GET /api/admin/imports/{importId}/items/{itemId}` — результат парсинга.
- `PUT /api/admin/imports/{importId}/items/{itemId}` — исправленные поля: title, description, eventDateTime, location, deadline, tagIds, mainImg. Даты nullable, в UTC с `Z`. URL источника неизменяемый.
- `POST /api/admin/imports/{importId}/items/{itemId}/confirm` — создаёт черновик с вручную подтверждёнными тегами, возвращает `eventId`. Повторные запросы возвращают то же мероприятие.
- `POST /api/admin/imports/{importId}/items/{itemId}/retry` — повторяет неудачную загрузку.

Статусы: Pending, Processing, Ready, Failed, Confirmed, Duplicate. Две фоновые задачи обрабатывают очередь; блокировки в PostgreSQL предотвращают одновременную обработку одной записи. После перезапуска просроченная блокировка подхватывается через две минуты. Подтверждение сериализовано по ITMO ID и защищено уникальным индексом. Изменённые вручную мероприятия не обновляются повторным импортом.

## Источник и ограничения

Поддерживаются только HTTPS-ссылки `itmo.events/events/{id}`. Перенаправления не выполняются. Загрузка ограничена 30 секундами и 4 МБ; временные сетевые ошибки повторяются до трёх попыток. Описание извлекается из публичной HTML-разметки, дата, адрес и изображение — также из JSON-LD. Время без UTC-offset трактуется как московское. Дата без года не угадывается. Дедлайн без структурированных данных остаётся пустым и требует ручной проверки.

Изображение из ITMO сохраняется как внешняя ссылка CDN. Админ может заменить его загрузкой через существующий S3-эндпоинт. Информация о доступности события для всех сейчас не классифицируется.

Миграция `AddEventImports` создаёт только две таблицы импорта и их индексы. Она применяется существующим механизмом миграций при запуске API. Для Docker добавлен проект EventImport в этап restore; compose и .env не требуют новых переменных.

## Будущая модель

Реализуйте `IEventImportEnricher` и зарегистрируйте его как scoped-сервис. `SuggestAsync` получает `ParsedEvent` и возвращает `ImportSuggestions`: описание и ID тегов из существующего справочника. Подсказки хранятся отдельно и применяются только по кнопке админа. Исходное описание сохраняется. Реализация должна учитывать CancellationToken; отведено 15 секунд на ответ. При сетевой ошибке помощника импорт продолжает работать вручную.

## Проверки

`dotnet test EventHubAPI/EventHubAPI.sln` запускает существующие и новые тесты. Интеграционные тесты PostgreSQL включаются переменной `EVENTHUB_IMPORT_TEST_CONNECTION` — строкой подключения пользователя с правом создать временную БД. Тесты создают отдельную БД со случайным именем и удаляют её после проверки; рабочие таблицы не меняются. В наборе есть HTTP-проверка admin JWT, очереди, редактирования и одновременного подтверждения через контроллеры.

Реальная HTML-разметка проверяется на сокращённом публичном фрагменте страницы мероприятия 122043, сохранённом в Fixtures. Прямой доступ к сайту зависит от сетевого подключения машины, на которой запущен API.
